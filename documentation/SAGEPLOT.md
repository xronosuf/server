# Sage plot SVG support

## Status

This document describes the experimental `sageplot` branch implementation.
It is intended for test-server validation before any production integration.

The author-facing source remains ordinary Ximera/SageTeX syntax:

```latex
\begin{image}
  \sageplot{plot(f(x), (x,-5,5))}
  \xmalt{Graph of ...}
\end{image}
```

For PDF output SageTeX retains its normal `\sageplot` behavior.  The Ximera
HTML configuration emits a web placeholder containing the authored Sage
expression:

```html
<span class="sage-plot">
  <script type="text/x-sage-plot">plot(...)</script>
</span>
```

## Runtime design

The browser implementation deliberately reuses the canonical page Sage
request rather than creating a second Sage request for a graph.

Before `main.js` captures the immutable pre-MathJax Sage manifest,
`sageplot-bootstrap.js`:

1. discovers `script[type="text/x-sage-plot"]` nodes;
2. injects one `text/sagemath` helper that serializes a Sage graphics object to
   SVG using a temporary SageCell-side file, reads that SVG, and removes the
   temporary file;
3. adds a hidden `.mathjax-inline` `\sagestr{...}` source beside each authored
   plot placeholder.

That hidden source is therefore captured, stable-ID annotated, evaluated, and
regenerated by the same canonical Sage machinery as ordinary `\sage` and
`\sagestr` occurrences.  The plot shares the same page seed, namespace,
request, and explicit `Another` generation.

`resolveMathJaxSageCall` is wrapped only for those synthetic plot expressions.
The canonical result is parsed as SVG, sanitized, and inserted into the
original `.sage-plot` element.  Ordinary Sage expressions are passed through
unchanged.

The SVG sanitizer removes script-capable embedded elements and event-handler
attributes before importing the result into the document.

## Browser diagnostics

On a page containing a Sage plot, run:

```javascript
xronosInspectSagePlots()
```

The result reports the number of prepared plots, render/failure counts, and
whether each plot currently has an SVG node.

The existing canonical Sage inspector remains useful:

```javascript
xronosInspectCanonicalPageSageRuntime()
```

The immutable manifest can be inspected with:

```javascript
xronosInspectInitialSagePageManifest()
```

The plot should appear there as an ordinary synthetic `sagestr` expression in
document order.

## Test-server validation checklist

Use the published `testSuite/14-sageplot-svg` activity.

1. Build the browser bundle successfully on the `sageplot` branch.
2. Confirm the page loads without a JavaScript or MathJax startup failure.
3. Confirm `xronosInspectSagePlots()` reports one plot with `hasSvg: true`.
4. Confirm the visible graph is an inline `<svg>`, not a raster image.
5. Confirm the displayed `a`, `h`, and `k`, the graph, and the vertex answer
   keys describe the same generation.
6. Reload normally and confirm the same seeded generation is retained.
7. Use **Another** and confirm the scalar values, answer keys, and graph change
   together in one generation.
8. Confirm the Another button remains busy until the generation is settled.
9. Confirm `\xmalt` remains present in the surrounding image environment.
10. Inspect the `/sagecell/service` response size and proxy cache behavior for
    the SVG-bearing canonical response before deciding whether the existing
    in-memory cache needs a separate body-size policy.

## Non-goals in the first implementation

- PNG fallback
- a separate Sage request per plot
- persistent plot files on the Xronos host
- independent plot random seeds
- web emulation of SageTeX's generated-file/includegraphics workflow
- final plot sizing or zoom UI
